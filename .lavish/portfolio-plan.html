Fresh Next.js starter. Default Geist font, no color theme, no page content yet. No design system to inherit from — this plan defines one.

Warm off-white background (not pure white) so cards and dividers read clearly. One restrained indigo-blue accent for links, buttons, and the hero graphic — evokes "technical/ML" without leaning on cliché green terminal or neon tones.

Typography & rhythm

Geist Sans — headings

Geist Sans — body, regular weight, 16-18px base

  • Keep the font already wired via next/font (Geist) — no new dependency, and it already reads clean/technical.
  • Differentiate hierarchy with weight and size only (700 for headings, 400-500 for body), not multiple families.
  • Section vertical padding: generous (96-140px desktop) so the page doesn't feel cramped despite being short.
  • Max content width ~1100-1200px, centered, with consistent horizontal gutter.

Hero visual — implementation approach

Animated scatter plot with a self-drawing regression line — decided, after weighing it against a neural network diagram and a particle/constellation network.

How it works

  • A dozen or so scatter points render in a loose upward trend, styled in soft indigo tones consistent with the accent palette.
  • A regression line draws itself across the chart on a slow, looping cycle, fading out briefly before redrawing — a quiet, continuous motion rather than a one-shot animation.
  • Subtle parallax: the whole chart shifts a few pixels toward the cursor/pointer position, capped and eased — not a full drag/zoom interaction.
  • Rendered beside the name text, never on top of it — never competing with legibility.

Technical & a11y notes

  • SVG over canvas for this concept — a fixed point count and a single animated path are cheap to animate with a CSS stroke-dasharray/stroke-dashoffset transition, and stay crisp at any resolution without a render loop.
  • Respect prefers-reduced-motion: freeze on the fully-drawn line, no redraw loop, no parallax.
  • Cap point count and simplify the chart on small viewports to protect mobile performance.
  • Purely decorative — mark aria-hidden="true", name text stays as real, accessible DOM content.
  • No external animation library needed; a CSS keyframe animation is enough for this scope.

Projects grid overflow strategy

Each category (Data Analysis, Machine Learning) renders its own grid independently, capped at one page of 6 cards (e.g. 3 columns × 2 rows). Project data lives in a typed array per category, not hardcoded markup — the grid component reads projects.slice(page * pageSize, ...) and only renders pagination controls when a category's project count exceeds the page size.

  • With 1 project per category today, no pagination UI renders at all — it appears automatically once needed.
  • Keeps the layout contract fixed regardless of content growth: adding project #7 to a category never reflows or breaks the grid, it just adds a page.
  • Avoids infinite-scroll or "load more" patterns, which read as busier than this page needs to be.

Decisions

Four calls that were open when this plan started, now settled and reflected throughout.

Hero visual: animated scatter plot with a self-drawing regression line.
Projects nav: anchor-scroll to two labeled subsections, no filter tabs.
CV download: include a "Download CV" button in the hero.
Project images: start with gradient + icon placeholders, swap in real screenshots later.

Suggested build order

  • Static structure & content
  • Design system & styling
  • Hero visual animation
  • Project data & grid/pagination
  • Responsive & a11y polish
  • Deploy to Vercel

Structure and styling first so the whole page is reviewable early, since this is the artifact recruiters will actually judge. Hero animation is isolated to its own step since it's the highest-complexity piece and shouldn't block content or styling work. Project data is modeled as a typed array from the start so pagination logic never needs retrofitting later.
